## Findings

### 1. The headline shield demo proves nothing on a host with modern keys - Friction

**Persona:** reviewer, checking the README's step 5 claim that `~/.ssh` and `~/.aws` stay unreadable under `read: "~"`.

**Transcript:**
```
$ export BENTO_PROBE_HOME="$HOME"
$ ./bento run broad-home.manifest.yaml --allow-unapproved
RESULT read.home-listing ALLOWED 127 entries
RESULT read.shield-.ssh-id_rsa DENIED FileNotFoundError: No such file or directory
RESULT read.shield-.aws-credentials DENIED FileNotFoundError: No such file or directory
RESULT read.shield-.bashrc DENIED FileNotFoundError: No such file or directory
[bento] sandbox engaged: 53 credential/host-service path(s) shielded (53 hidden)

$ ls -A ~ | wc -l
127
$ ls -la ~/.bashrc ~/.ssh/id_rsa ~/.aws/credentials
"/home/jrose/.ssh/id_rsa": No such file or directory
"/home/jrose/.aws/credentials": No such file or directory
.bashrc -> /nix/store/...-home-manager-files/.bashrc
$ ls ~/.ssh
authorized_keys  id_ed25519  id_ed25519.pub  known_hosts  known_hosts.old
```

**Why it bites:** the probe README says "only read the shield results as meaningful when
that count is close to the host's". It is (127 vs 127), so the reader trusts three DENIEDs
that are all "file does not exist": ed25519 has been the `ssh-keygen` default for years, most
hosts have no `~/.aws/credentials`, and a symlinked dotfile resolves outside the grant. The
shield does hold - a hand-written probe of `~/.ssh/id_ed25519` under the same grant got
ENOENT and `~/.ssh` listed empty - but the demo shipped to show it does not show it.

**Fix:** probe the shielded *directories* rather than guessed filenames (`~/.ssh` listing
should come back empty while the host's is not), and have the README tell the reader to
compare that against `ls ~/.ssh` the way it already does for the home count.

### 2. A host with no bubblewrap gets the fix in line 2 of a 115-line report - Friction

**Persona:** arrives broken - a stock Ubuntu 24.04 with no `bwrap`, which the README names
as the likeliest first-run failure.

**Transcript:**
```
$ env PATH=/usr/bin/nonexist bento doctor; echo rc=$?
rc=3
$ wc -l doctor.txt
115
filesystem (degraded):
  bubblewrap (bwrap) is not installed, so it cannot isolate anything. Install
  it with your package manager (Debian/Ubuntu: sudo apt install bubblewrap; ...
  ... [a single paragraph of ~60 lines, one sentence of which runs ~20 lines,
  covering Landlock ABI 9, MPTCP, TIOCSTI, PR_CAPBSET_DROP ...]
...
A core guarantee every run needs is not fully enforced here. Runs are refused
by default; --allow-degraded opts into a weaker sandbox, knowingly.
```

**Why it bites:** the one actionable line is there, but the closing summary the eye lands on
offers `--allow-degraded`, not the install. A user who reads the bottom takes the escape
hatch instead of the one-command fix.

**Fix:** when the cause is a missing `bwrap`, end the report with the install command, and
move the degraded-tier caveats behind the note they already belong to (or a `--verbose`).

### 3. `profile` says the host has no `/tmp` - Polish

**Persona:** new hire, Quick Start step 1.

**Transcript:**
```
$ ./bento profile ./probe.py < /dev/null
[bento] not proposing write access to "/tmp" - no such directory exists on the host, so
inside the box that name is in the private /tmp every run mounts ...
$ ls -ld /tmp
drwxrwxrwt - root root 21 Sep 21:19 /tmp
```

**Why it bites:** the reader knows `/tmp` exists, so the first explanation they get from
profile is visibly wrong, which costs trust in the ones that follow. The probe wrote
`/tmp/bento-probe.txt`; the message reports the parent directory, which does exist.

**Fix:** name the written path, not its directory, or say "every /tmp path is the run's own
scratch" without the claim about the host (`cmd/bento/profile.go:1232`).
